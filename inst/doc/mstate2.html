Second-order Markov multistate models with mstate2

library(mstate2)

Why second order?

A first-order Markov multistate model assumes the future depends only on the current state. A second-order model relaxes this: the next state may also depend on the previous state, capturing short-term memory. mstate2 estimates the 1-step second-order transition probabilities

\[P_{hj\ell} = P(X_s = \ell \mid X_{s-1} = j,\; X_{s-2} = h),\]

provides confidence intervals, predicts any number of steps ahead via an extended Chapman–Kolmogorov relation, and constructs evolution intervals to test whether — and for how long — the preceding state matters.

A worked example

We simulate a three-state process. From state B the one-step-ahead behaviour depends on whether the patient arrived from A or from B:

st   <- c("A", "B", "C")
tens <- array(0, c(3, 3, 3), dimnames = list(st, st, st))
tens["B", "B", "A"] <- 0.6; tens["B", "C", "A"] <- 0.4   # from (A,B): stay 0.6
tens["B", "B", "B"] <- 0.3; tens["B", "C", "B"] <- 0.7   # from (B,B): stay 0.3
tens["C", "C", ]    <- 1                                  # C absorbing
first <- matrix(0, 3, 3, dimnames = list(st, st)); first["A", "B"] <- 1

set.seed(1)
panel <- simulate2(5000, tens, first, init = c(A = 1, B = 0, C = 0))
head(panel)
#>    id time state
#> 1:  1    0     A
#> 2:  1    1     B
#> 3:  1    2     B
#> 4:  1    3     C
#> 5:  2    0     A
#> 6:  2    1     B

Estimation

prep2() builds the second-order counting processes; P2est() estimates the probabilities with the relative probability estimator (RPE, the recommended default) or the conditional probability estimator (CPE).

d   <- prep2(panel, id = "id", time = "time", state = "state")
fit <- P2est(d, estimator = "RPE")
fit$estimate
#>   h j l        p          se     lower     upper
#> 1 A B B 0.598600 0.006932215 0.5850131 0.6121869
#> 2 A B C 0.401400 0.006932215 0.3878131 0.4149869
#> 3 B B B 0.293604 0.006996420 0.2798912 0.3073167
#> 4 B B C 0.706396 0.006996420 0.6926833 0.7201088

The estimates recover the truth: A -> B -> B near 0.6, B -> B -> B near 0.3.

Prediction

ckequations() propagates the 1-step estimates to any horizon:

ckequations(fit, h = "A", j = "B", l = "B", nsteps = 6)
#> [1] 0.598600000 0.175751333 0.051601288 0.015150343 0.004448201 0.001306009

Evolution intervals

compare2() contrasts the trajectories for different preceding states and attaches evolution intervals; summary() reports the duration of the effect.

cmp <- compare2(fit, h = c("A", "B"), j = "B", l = "B", nsteps = 9)
summary(cmp)
#> Evolution-interval comparison (RPE, 95% bounds)
#>   target 'B' via current state 'B'
#>   intervals first overlap at step n = 8 (time s = 9)
#>   -> preceding state ('A' vs 'B') has a significant effect
#>      for at least the first 7 step(s).
plot(cmp, type = "interval")

Non-overlapping evolution intervals imply a statistically significant effect of the preceding state. Here the two trajectories are clearly separated in the early steps, quantifying how long the second-order memory persists.

Real data and interoperability

For sojourn-time datasets (such as the DIVINE COVID-19 cohort), use sojourn_to_panel() to obtain panel data, then proceed as above. as_tmat() returns an mstate::transMat transition matrix so the model can be read alongside a first-order mstate analysis. See the reproduction scripts in the package tests/ directory for an end-to-end analysis of the DIVINE data.
